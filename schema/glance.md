# Glance · 论文速览模板

`glance` 是完成初步调研后的阅读价值判断。它应让读者在几分钟内知道论文做了什么、证据是否可信、当前是否值得投入精读时间。它不能只重写摘要。

## 默认结构

```markdown
# 论文标题

## 研究问题与价值
## 已有解法与缺口
## 方法与核心直觉
## 观点与结论
## 实验与验证
## Takeaways
## 深度判断
## 与 Wiki 的连接
## 来源与证据边界
```

## 内容要求

1. 说明论文提出并解决的研究问题，补充理解问题所需的背景，并解释解决后的研究或工程价值。
2. 说明此前已有方法，以及论文认为它们为何不足。相关工作的结论必须来自可核验的一手来源或论文自身的 related work。
3. 先简要保留论文原本的 problem setting / formulation、输入输出和方法步骤，再补充清楚、简洁的 intuition。速览可以压缩细节，但不能改变任务定义、模块关系或流程顺序。
4. 分开记录作者提出的观点、作者报告的结论，以及阅读者根据证据做出的判断。
5. 说明作者用哪些实验验证哪些 claim。优先写实验逻辑，不堆表格数字。
6. 用一个小卡片总结：`问题`、`核心 idea`、`最强证据`、`主要风险`、`何时有用`。
7. 给出 `保持 glance` 或 `升级 deepnote` 的判断和理由。保持 glance 时，明确什么新问题或新证据会触发升级。

信息不足时标明阅读范围。只读摘要、博客或二手解读不能写成完整判断；此时必须降低结论强度。
