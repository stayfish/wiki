# 论文阅读与深度路由

论文页面保存到 `wiki/sources/<slug>.md`。先做价值判断，再选择 [`glance.md`](./glance.md) 或 [`deepnote.md`](./deepnote.md)。页面要让未来读者恢复“论文解决了什么、为什么值得关心、方法怎样工作、凭什么相信、与已有认识有什么关系”。方法论文应覆盖核心机制、关键算法和真正帮助理解的图表。

## 建议额外元数据

```yaml
source_kind: paper
source_url: https://example.com/paper
source_version: arXiv v1
read_scope: full-text
status: reviewed
```

`read_scope` 可用 `full-text`、`abstract`、`excerpt` 或明确页码范围。缺失正文时不得把摘要阅读写成全文阅读。

## 来源与取证

- 优先读取用户提供的 PDF；否则使用作者、arXiv、会议或项目官方版本。搜索只用于补背景、核验相关工作和追踪后续研究，技术性结论优先引用一手资料。
- `deepnote` 原则上要求可用全文。若 PDF/HTML 证据不足、公式或图表无法可靠读取，应停止在 `glance`，明确缺口，不生成降级版 deepnote。
- 记录论文身份、版本、发布日期、阅读日期和实际阅读范围。论文、代码与项目页版本不一致时分别记录。
- 先查 `index.md` 和相关 Wiki 页。新来源必须支持、修正、反驳或细化已有结构；确实没有连接时再创建真实概念或开放线索。

## 深度判断

完成六项判断后，按以下维度决定深度：

- 与读者当前问题及 Wiki 主线的相关性；
- 相对已有工作的真实知识增量；
- 方法、结果或失败模式能否迁移到其他问题；
- claim 是否有可检查的实验支撑；
- 论文是否披露了足够方法和设置，允许深入分析。

会议、作者声望、模型规模和排行榜名次只能作为上下文，不能替代判断。`glance` 不表示论文质量差，只表示当前边际阅读价值不足；`deepnote` 也不等于同意论文结论。

## 写作与证据

- 区分论文声称、相关文献的结论、分析推断、未知猜测和用户判断。
- 不把排行榜领先自动写成普遍优越；记录数据集、指标、工具和推理设置。
- 论文提出的新术语不一定值得独立概念页；只有跨来源复用时才拆出。
- 对代码论文，注明论文、仓库和实际检查到的代码版本是否一致。
- 对用户在对话中提出的批评，写成“用户关注”或“阅读判断”，不要归给作者。
- 方法部分先写“原文忠实层”：保留论文的 problem setting / formulation、研究对象、观测与目标变量、假设、输入输出、符号定义、模块依赖，以及训练和推理的原始顺序。术语可翻译，但不能用近似概念替换技术定义。
- 随后再写“解释层”：用直觉、例子或重新组织的图示帮助理解。凡是 Agent 为教学目的重排的流程，都要明确标为解释性重组，并说明它与论文原始流程的对应关系。
- 论文没有交代的步骤保持未知；不能根据常见实现补写成作者方法。论文多个章节对同一流程表述不一致时，保留差异并注明位置或版本。
- 正式精读前先恢复论文的论证树：背景和已有挑战如何导向观察或猜想，猜想如何导向方法，实验如何分别支撑 claim，贡献与局限落在哪些证据上。树中的节点可以跨越论文相邻章节，但必须记录原文章节映射。
- 讨论与最终页面沿用同一棵树。一级块使用 `##`，块内可继续用 `###` 拆分；模板检查项可以合并进语义相近的块，不能为了套模板打散原论文逻辑。
- 同步检查全文图表。优先选择能恢复方法数据流的总览图、支撑主 claim 的结果表、改变因果判断的消融和暴露边界的失败样例；每项都要写明“它证明什么”和“它不能证明什么”。
- 相关工作背景不能倒因为果。重建作者思路时，只使用该论文发表前可获得的知识、失败模式和经验观察；该部分必须明确是分析性重建，不冒充作者自述。
- 实验部分按“问题 → 实验 → 答案”组织，明确实验支持的范围。缺少关键消融时应直接写“无法归因”，不能用主结果替代。
