# Wiki Schema · 阅读笔记总契约

本目录定义人与 Agent 如何通过对话，把阅读过程编译成一个持续演化的 Wiki。它采用 LLM Wiki 的核心分层：`raw/` 保存不可变来源，`wiki/` 保存 Agent 维护的知识，schema 约束每次对话如何读、写、连接和校验。

## 目标

这不是“每篇材料生成一份摘要”的归档器，而是阅读伙伴与长期记忆层：

- 人选择材料、说明为什么读、追问、纠偏并审核结果。
- Agent 阅读来源，提出值得讨论的要点，把确认后的认识写入 Wiki。
- 新材料应修订已有理解、补充证据或暴露冲突，而不只是增加孤立页面。
- 后续回答优先使用已经编译的 Wiki；只有核验和补缺时才回到原始来源。

## 工作记录与三层知识结构

- `sessions/`：本地对话工作区。一个目录对应一篇论文或一条连续研究线程，保存多轮讨论的 Markdown 与静态 HTML；默认不提交、不发布，也不是知识事实来源。

- `raw/`：来源文件或来源指针。保存后不可静默改写，是可追溯的事实底座。
- `wiki/`：可读的 Markdown 知识页，由 Agent 创建和维护，人负责审核。
- `schema/`：写作模板和对话工作流，由人与 Agent 共同调整。
- `evidence/`：页面结构与证据 sidecar；保存稳定 block ID、claim 类型、核验状态和原文锚点，遵循 [`evidence.md`](./evidence.md)。

`index.md` 是按内容组织的紧凑地图；`log.md` 是按时间追加的操作记录。两者用途不同，不能互相替代。

## 页面类型与模板

- `wiki/sources/`：单一来源的阅读笔记。`glance` 是完成价值判断后的速览，遵循 [`glance.md`](./glance.md)；`deepnote` 是在全文取证、分块阅读和讨论后编译的深入阅读结果，遵循 [`deepnote.md`](./deepnote.md)。两者共同遵循 [`source.md`](./source.md)，论文还应用 [`paper.md`](./paper.md) 的取证规则。
- `wiki/concepts/`：跨来源复用的机制或概念；遵循 [`concept.md`](./concept.md)。
- `wiki/topics/`：多个来源形成的比较、综述或判断；遵循 [`topic.md`](./topic.md)。
- `wiki/threads/`：尚未闭合、值得继续追踪的问题；遵循 [`thread.md`](./thread.md)。

操作顺序、对话暂停点和触发语见 [`conversation.md`](./conversation.md)，对话与页面共用的语言组织规则见 [`writing.md`](./writing.md)。只有出现真实内容时才创建目录或页面。

Session 遵循 [`session.md`](./session.md)。Session 中可以保留探索、纠偏和未决猜测；写入 Wiki 时必须重新核对来源、压缩重复内容并按页面类型分流，不能把对话记录直接当成已审核知识。

## 通用 Frontmatter

```yaml
---
title: 页面标题
slug: unique-kebab-case
type: deepnote
summary: 一句可独立显示的摘要
updated: 2026-09-28
accent: moss
---
```

- `slug`：唯一英文 kebab-case。
- `type`：只能是 `glance`、`deepnote`、`concept`、`topic`、`thread`。旧的 `source` 类型不得用于新页面。
- `summary`：说明读者为什么应该打开该页，不重复标题。
- `updated`：实际发生内容变化的日期；不要因机械检查改日期。
- `accent`：只能是 `brick`、`ochre`、`moss`、`deep`。
- 内部链接：使用 `[[slug]]` 或 `[[slug|显示文字]]`，目标必须存在。

模板可以要求额外元数据，但不得改变构建器所需字段。

Deepnote 应建立同 slug 的 `evidence/<slug>.json`。构建器优先使用 sidecar 中的稳定 ID；正文改标题或重排时更新标题路径，但不得仅因顺序变化重建 ID。Claim 与来源锚点的字段和状态迁移遵循 [`evidence.md`](./evidence.md)。

## 写作与证据规则

- 先写问题、结论和直觉，再写机制与细节。
- 严格区分四类信息：论文原文明确声称的内容、相关文献中的已有结论、基于证据的合理推断、仍不确定的猜测。推断不能写成事实；猜测必须说明缺少什么证据。
- 重要主张指回来源页；来源页注明 URL、本地文件、版本、访问日期和阅读范围。
- 不编造引文、页码、代码位置、作者立场、实验数字或因果关系。
- 摘要、解释、批评和用户观点不能伪装成来源原话。
- 总结方法时保留论文原本的问题设定、任务定义、假设、输入输出、符号含义和流程顺序。Agent 的直觉解释、类比与重组必须与原文忠实层分开，不能改写成论文没有定义的新问题或新 pipeline。
- deepnote 精读先用“旧方法 → 具体失败 → 本文改动 → 预期行为 → 证据责任”完成整体定向，再建立可递归拆分的读者地图。一级块优先沿用背景与相关工作、观察与核心 idea、方法、实验与论证、贡献与局限等正常论文结构；每块必须说明认知目标，不能只摘录章节、问题和术语。
- 面向用户的读者地图与 Agent 取证计划分离。前者使用已解释的自然语言，默认只有 4–6 个一级块；后者维护章节、公式、图表、claim、证据状态、版权处理和依赖关系。每块结束后吸收用户讨论并允许修订后续地图。最终页面的 `##` 对应实际讨论中的一级块，`###` 对应子块；模板要求用于检查覆盖率，不用于强制所有论文采用同一线性目录。
- 每篇 deepnote 必须包含在全文阅读后完成的忠实中文摘要翻译，并使用固定的 `## 摘要翻译` 与分析正文分开。
- 同一概念只有一个主页面；出现同义内容时更新或合并，不创建近似副本。
- 有冲突时并列记录双方主张、证据和未决原因，不擅自取平均或抹平。
- 链接要说明关系，例如“提供证据”“形成反例”“细化机制”，而不是堆砌“相关链接”。

## 写作风格

- 统一遵循 [`writing.md`](./writing.md) 的问题驱动 workflow。先给具体失败或疑问，再沿直接做法、缺口、设计、行为和证据边界推进；不要把原文顺序翻译成中文后堆叠。
- 术语以准确、自然和可查证为准。原文术语比生硬译法清楚时保留英文，首次解释后保持一致，不追求中文化率。
- 使用准确、细粒度的 claim；每句话尽量包含对象、条件、机制、证据或边界，删除泛泛评价。
- 以流畅正文组织论证，只在并列关系确实更清楚时使用列表。少用破折号和引号，不用“不是……而是……”制造空洞对比。
- 背景深度以 [`reader-profile.md`](../reader-profile.md) 为准。已知基础只需定位，论文特有的新机制仍需从直觉讲到形式化表达。
- 清晰来自准确重建。原文 formulation 或流程存在歧义时，保留歧义并指出缺失信息，不自行补成完整故事。
- 公式只使用 Markdown 数学语法 `$...$` 与 `$$...$$`，变量首次出现时定义，并解释每一步推导服务于哪个机制判断。
- 先做事实与证据检查，再做独立的可读性检查。抽象名词若不能对应到一个动作、状态或可测量现象，应改写或删除。

## 写入门槛

以下内容适合持久化：

- 对来源的可复查阅读笔记；
- 能在其他来源中复用的概念；
- 跨来源比较或新综合；
- 会影响未来阅读方向的开放问题；
- 用户明确要求保留的批注或判断，并标记为用户观点。

以下内容默认只留在对话中：

- 临时澄清、寒暄和操作说明；
- 没有证据且复用价值低的猜测；
- 与现有页面重复的改写；
- 用户尚未确认、而且会显著改变笔记重点的 Agent 推断。

## Index 与 Log

`index.md` 按页面类型列出每一页的 `[[slug]]` 和一句导航说明。它要足够短，让 Agent 先读完整索引再选择少量页面。

`log.md` 只追加操作记录，标题格式保持可搜索：

```markdown
## [2026-09-28] ingest | 来源标题
## [2026-09-28] query | 问题摘要
## [2026-09-28] lint | 检查范围
```

记录本次新增、修订、冲突、未决项和材料完整度，不复制整篇内容。

## 图示

只有当图比文字明显更容易解释关系、流程或时间顺序时才添加内联 SVG。SVG 必须有 `viewBox`、`role="img"`、`aria-labelledby` 和 `<title>`，窄屏可读，关闭动画后仍表达完整含义。可用类为 `reveal`、`draw`、`grow-x`、`pulse`，用 `d1` 至 `d8` 控制顺序。

论文截图与结果图表遵循以下规则：

- 先列图表决策表，记录原始图号/表号、目标讨论块、它支持的 claim、处理方式和版权状态。优先保留方法总览、关键数据流、主结果、决定性消融和失败案例。
- 许可允许再发布时，将清晰裁剪保存到 `assets/papers/<slug>/`；保留坐标轴、图例、方法名和理解结论所需的表头，不截成失去实验条件的孤立数字。
- 许可不明确或禁止再发布时，不提交原图截图。结构图使用明确标注为“据原文重绘”的 SVG；实验结果使用注明原始表号的 Markdown 表格重建必要行列，并链接论文。
- 每张图都要有描述性 alt、原始图号或表号、来源链接和解释。截图本身不替代正文论证。

## Deepnote 页面呈现

- 构建器根据 `## / ###` 层级生成阅读地图、一级卡片与卡片内子块；内容结构必须来自论文与实际讨论，不为视觉效果伪造分块。
- 卡片的语义角色由标题和内容类型生成，例如 Context、Insight、Method、Evidence、Contribution、Critique、Frontier、Reference。语义角色只影响呈现，不改变证据等级。
- 页面可提供章节跳转、折叠/展开、聚焦阅读、复制块链接和阅读进度等渐进增强交互。关闭 JavaScript 时，正文仍须完整、顺序正确且可阅读。
- Rich Response 优先使用真正有信息结构的公式、代码、图示、结果表与内部链接；禁止用装饰组件制造虚假丰富度。
- deepnote 必须包含独立的“摘要翻译”块。构建器将它渲染为区别于分析卡片的 Abstract Translation 卡；该块只翻译论文摘要，不混入背景补充、评价或 Agent 推断。

## 完成标准

一次持久化操作只有在以下条件全部满足时才完成：

- 来源范围和证据边界明确；
- 页面遵循对应模板；
- 新知识已合并或连接到现有结构；
- `index.md` 与 `log.md` 已同步；
- Wiki 链接、构建结果和 `manifest.json` 已验证；
- Agent 向用户报告写入内容、关键连接、未知项、提交与发布状态。
