# Wiki Schema · 阅读笔记总契约

本目录定义人与 Agent 如何通过对话，把阅读过程编译成一个持续演化的 Wiki。它采用 LLM Wiki 的核心分层：`raw/` 保存不可变来源，`wiki/` 保存 Agent 维护的知识，schema 约束每次对话如何读、写、连接和校验。

## 目标

这不是“每篇材料生成一份摘要”的归档器，而是阅读伙伴与长期记忆层：

- 人选择材料、说明为什么读、追问、纠偏并审核结果。
- Agent 阅读来源，提出值得讨论的要点，把确认后的认识写入 Wiki。
- 新材料应修订已有理解、补充证据或暴露冲突，而不只是增加孤立页面。
- 后续回答优先使用已经编译的 Wiki；只有核验和补缺时才回到原始来源。

## 三层结构

- `raw/`：来源文件或来源指针。保存后不可静默改写，是可追溯的事实底座。
- `wiki/`：可读的 Markdown 知识页，由 Agent 创建和维护，人负责审核。
- `schema/`：写作模板和对话工作流，由人与 Agent 共同调整。

`index.md` 是按内容组织的紧凑地图；`log.md` 是按时间追加的操作记录。两者用途不同，不能互相替代。

## 页面类型与模板

- `wiki/sources/`：单一来源的阅读笔记，遵循 [`source.md`](./source.md)；论文再应用 [`paper.md`](./paper.md) 的专门规则。
- `wiki/concepts/`：跨来源复用的机制或概念；遵循 [`concept.md`](./concept.md)。
- `wiki/topics/`：多个来源形成的比较、综述或判断；遵循 [`topic.md`](./topic.md)。
- `wiki/threads/`：尚未闭合、值得继续追踪的问题；遵循 [`thread.md`](./thread.md)。

操作顺序、对话暂停点和触发语见 [`conversation.md`](./conversation.md)。只有出现真实内容时才创建目录或页面。

## 通用 Frontmatter

```yaml
---
title: 页面标题
slug: unique-kebab-case
type: source
summary: 一句可独立显示的摘要
updated: 2026-09-28
accent: moss
---
```

- `slug`：唯一英文 kebab-case。
- `type`：只能是 `source`、`concept`、`topic`、`thread`。
- `summary`：说明读者为什么应该打开该页，不重复标题。
- `updated`：实际发生内容变化的日期；不要因机械检查改日期。
- `accent`：只能是 `brick`、`ochre`、`moss`、`deep`。
- 内部链接：使用 `[[slug]]` 或 `[[slug|显示文字]]`，目标必须存在。

模板可以要求额外元数据，但不得改变构建器所需字段。

## 写作与证据规则

- 先写问题、结论和直觉，再写机制与细节。
- 将“来源明确陈述”“Agent 的综合或推断”“仍未知”分开表达。
- 重要主张指回来源页；来源页注明 URL、本地文件、版本、访问日期和阅读范围。
- 不编造引文、页码、代码位置、作者立场、实验数字或因果关系。
- 摘要、解释、批评和用户观点不能伪装成来源原话。
- 同一概念只有一个主页面；出现同义内容时更新或合并，不创建近似副本。
- 有冲突时并列记录双方主张、证据和未决原因，不擅自取平均或抹平。
- 链接要说明关系，例如“提供证据”“形成反例”“细化机制”，而不是堆砌“相关链接”。

## 写入门槛

以下内容适合持久化：

- 对来源的可复查阅读笔记；
- 能在其他来源中复用的概念；
- 跨来源比较或新综合；
- 会影响未来阅读方向的开放问题；
- 用户明确要求保留的批注或判断，并标记为用户观点。

以下内容默认只留在对话中：

- 临时澄清、寒暄和操作说明；
- 没有证据且复用价值低的猜测；
- 与现有页面重复的改写；
- 用户尚未确认、而且会显著改变笔记重点的 Agent 推断。

## Index 与 Log

`index.md` 按页面类型列出每一页的 `[[slug]]` 和一句导航说明。它要足够短，让 Agent 先读完整索引再选择少量页面。

`log.md` 只追加操作记录，标题格式保持可搜索：

```markdown
## [2026-09-28] ingest | 来源标题
## [2026-09-28] query | 问题摘要
## [2026-09-28] lint | 检查范围
```

记录本次新增、修订、冲突、未决项和材料完整度，不复制整篇内容。

## 图示

只有当图比文字明显更容易解释关系、流程或时间顺序时才添加内联 SVG。SVG 必须有 `viewBox`、`role="img"`、`aria-labelledby` 和 `<title>`，窄屏可读，关闭动画后仍表达完整含义。可用类为 `reveal`、`draw`、`grow-x`、`pulse`，用 `d1` 至 `d8` 控制顺序。

## 完成标准

一次持久化操作只有在以下条件全部满足时才完成：

- 来源范围和证据边界明确；
- 页面遵循对应模板；
- 新知识已合并或连接到现有结构；
- `index.md` 与 `log.md` 已同步；
- Wiki 链接、构建结果和 `manifest.json` 已验证；
- Agent 向用户报告写入内容、关键连接、未知项、提交与发布状态。
