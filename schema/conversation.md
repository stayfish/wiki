# 对话工作流

用户不需要记命令。Agent 应根据自然语言判断当前是阅读判断、深入阅读、追问、沉淀还是体检，并在回复中明确当前阶段。

## 默认：互动阅读

当用户提供论文并说“阅读”“看看”“做笔记”时，默认分四步。其他来源沿用同一原则，但可按媒介调整判断项。

### 第一步：判断阅读价值

1. 确认来源位置、公开版本和可读取范围，说明读到全文、摘要还是节选。
2. 阅读 `index.md` 和相关页面，指出它与已有知识的可能关系。
3. 阅读论文并做必要的一手来源搜索，给出六项判断：
   - 研究问题、重要性和潜在价值；
   - 此前解法及其具体不足；
   - 方法、intuition 与核心 idea；
   - 作者观点与结论；
   - 实验怎样验证方法和 claim；
   - takeaways 小卡片。
4. 给出 `glance` 或 `deepnote` 建议，说明相关性、知识增量、证据强度、方法可复用性和披露完整度。
5. 此阶段不修改 Wiki，等待用户追问、纠偏或确认重点。

如果用户明确说“直接入库”“无需先讨论”或已经给出清晰阅读目标，可以跳过暂停点，由 Agent 依据判断直接选择页面深度。

### 第二步：建立分层阅读地图

- 判断为 `glance`：把六项判断整理为紧凑速览，并写明保持 glance 的理由与升级触发条件。
- 判断为 `deepnote`：先通读全文的章节、图表与论证链，输出一棵可调整的阅读地图。默认一级块包括：问题背景、相关工作与挑战；作者的观察、灵感和猜想；提出的方法；实验、结论与论证；工作贡献；工作局限。若块内包含多条独立问题链、方法阶段或实验 claim，继续拆成子块。
- 每个块注明它覆盖的原文章节或图表、要回答的核心问题，以及与前后块的依赖。分块服务于理解，不能把论文原本相互依赖的步骤拆成无关碎片。
- 同步生成图表计划：逐一检查方法图、主结果表、关键消融和失败案例，记录它们将进入哪个块、支持什么 claim、采用原图截取还是重绘/表格重建。
- 向用户展示阅读地图并允许调整顺序、合并、拆分或指定重点。不同调整不会改变证据事实，只改变讨论路径。
- 用户可以覆盖深度判断。用户明确要求 deepnote 时，只要来源充分就执行；若来源不足，说明需要的 PDF、OCR 或版本。

### 第三步：逐块精读与讨论

1. 按确认后的阅读地图逐块推进；默认一次讨论一个一级块，复杂块按子块推进。
2. 每块依次给出：原文在解决什么、原文依据与 formulation、易懂解释、关键图表或实验结果、证据边界、局限与当前未知、与 Wiki 的连接。
3. 每个一级块结束时暂停，吸收用户追问、纠偏和判断，再进入下一块。用户明确要求连续精读时可以不暂停，但仍保留块边界。
4. 将用户确认的重点、反对意见和解释选择绑定到对应块，避免最后统一堆进“用户观点”附录。

### 第四步：写入与重构

用户说“写入 Wiki”“按这个重点整理”“把刚才的讨论保留下来”后：

1. 在 `raw/` 保存合法的小型材料或来源指针，不复制无权发布的全文。
2. 创建或更新对应来源页，设置 `type: glance` 或 `type: deepnote`。deepnote 使用讨论时确认的一级块作为 `##`、子块作为 `###`，同时检查模板要求是否全部被覆盖；同一来源升级时原地修改，不建立重复页面。
3. 更新所有真正受影响的概念、主题和开放问题页；不要为了显得完整而强行拆页。
4. 回写对话中产生且用户确认的解释、比较或批评，将其与许可合规的关键图表一起放回对应讨论块，并明确标注性质与来源。
5. 更新 `index.md` 和 `log.md`，运行完整验证并提交当前任务相关改动。
6. 报告写了什么、改变了什么、还有什么未知；未经明确要求不 push 或发布。

## 追问

当用户围绕已读材料追问：

1. 先从 `index.md` 定位少量 Wiki 页并基于现有笔记回答。
2. 关键事实不确定、页面互相冲突或证据不足时，再回到 `raw/` 或公开原文。
3. 回答中区分论文声称、相关文献、分析推断与未知，并链接相关页面。
4. 默认不写文件；只有用户要求保留，或本轮一开始已经授权持续记笔记时才回写。
5. 回写时优先修订已有页；只有形成独立、长期有用的知识对象时才新建页。

## Lint 与回顾

用户说“整理笔记”“检查知识库”“回顾最近阅读”时：

- 结构检查：死链、孤儿页、重复页、frontmatter 和目录不一致。
- 知识检查：矛盾、过时主张、缺少来源的强断言、薄弱概念和未闭合线索。
- 深度检查：glance 是否足以支持深度判断；deepnote 是否覆盖完整论证、反例、复现和后续研究。
- 结构检查：deepnote 是否保留讨论时确认的分块树，子块是否仍能说明其上位问题，固定模板是否误压平了论文结构。
- 图表检查：关键方法图和决定性实验是否进入对应块，裁剪是否保留坐标、图例与条件，版权不明的原图是否已改为重绘或表格重建。
- 阅读回顾：近期来源改变了哪些既有认识，还有哪些问题值得读下一篇材料。
- 可安全判断的问题直接修复；需要用户取舍的解释冲突先讨论。

## 常用说法

```text
判断这篇论文是否值得精读，先和我讨论，不要写入 Wiki：<路径或 URL>
```

```text
按“方法为什么有效”这个重点，把它升级为 deepnote。
```

```text
先给我这篇论文的分层阅读地图和关键图表计划，再按块讨论；每个一级块结束后暂停。
```

```text
直接把这篇论文入库；先判断深度，值得精读就生成 deepnote，否则保存 glance。
```

```text
根据现有 Wiki 回答这个问题。先不要修改文件：<问题>
```

```text
把刚才的答案沉淀成主题页，并更新受影响的旧页面。
```

```text
回顾最近五次阅读：哪些结论变强了，哪些仍有冲突，下一步该读什么？
```
