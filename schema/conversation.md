# 对话工作流

用户不需要记命令。Agent 应根据自然语言判断当前是阅读判断、深入阅读、追问、沉淀还是体检，并在回复中明确当前阶段。

所有对话回答遵循 [`writing.md`](./writing.md)。先从用户当前困惑对应的具体场景开始，再引出术语、机制、公式和证据；原词更清楚时保留英文，不为了形式完整重复论文目录或把证据标签机械塞进每段。

## 默认：互动阅读

当用户提供论文并说“阅读”“看看”“做笔记”时，默认分四步。其他来源沿用同一原则，但可按媒介调整判断项。

开始阅读时创建或续写一个本地 session：同一篇论文或同一条连续研究线程共用一个 session，每轮用户问题与 Agent 回答作为新的 turn 追加。用户输入和 Agent 完整回答均按原文保存，不使用摘要、忠实压缩或省略标记代替原文。Agent 先将完整回答写入 session，再更新 `sessions/<session-slug>/index.html`；Codex 对话区的最终回复只提供该本地页面链接，不再复制回答正文。Session 不使用独立的滚动摘要文件，也不自动写入公开 Wiki。

### 第一步：判断阅读价值

1. 确认来源位置、公开版本和可读取范围，说明读到全文、摘要还是节选。
2. 阅读 `index.md` 和相关页面，指出它与已有知识的可能关系。
3. 阅读论文并做必要的一手来源搜索，给出六项判断：
   - 研究问题、重要性和潜在价值；
   - 此前解法及其具体不足；
   - 方法、intuition 与核心 idea；
   - 作者观点与结论；
   - 实验怎样验证方法和 claim；
   - takeaways 小卡片。
4. 给出“保持 `glance`”或“值得进入精读”的建议，说明相关性、知识增量、证据强度、方法可复用性和披露完整度。
5. 此阶段不修改 Wiki，等待用户追问、纠偏或确认重点。

如果用户明确说“直接入库”或“无需先讨论”，可以跳过用户暂停点，但 Agent 仍必须完成价值判断、全文取证和按块分析；不能将一次速读或摘要阅读写成 deepnote。

### 第二步：整体定向与双层阅读地图

- 建议保持 `glance`：把六项判断整理为紧凑速览，并写明保持 glance 的理由与升级触发条件。
- 用户确认进入精读：先通读全文的章节、图表与论证链，再用一段自然语言或一条短因果链完成整体定向：旧系统怎样工作、在什么条件下失效、本文改变哪个表示/接口/训练信号、作者预期出现什么行为、什么实验才能区分真实解决与表面改善。定向中只保留理解主线必需的术语，并当场解释。
- 在整体定向上建立面向用户的读者地图。默认使用 4–6 个一级块，沿正常论文阅读顺序组织：问题背景与价值；相关工作与挑战；观察、动机与核心 idea；方法与数学；实验与论证；贡献、局限与后续问题。每块只需回答三件事：`要理解什么`、`为什么现在读`、`读完后能判断什么`。块内的独立问题链和方法阶段进入该块后再递归展开。
- 读者地图不能用尚未解释的专有名词、缩写、公式变量、benchmark 名称、图号或表号充当子块。不可避免地首次提及论文术语时，使用“白话含义（原文术语）”，让读者即使删去专有名词也能理解各块为何存在和怎样衔接。
- Agent 同时维护独立的取证计划，记录每块覆盖的章节、公式、图表、claim、证据状态、前后依赖以及截图/重绘/表格重建的处理方式。该计划保证严谨性，但默认不塞进读者地图；进入对应块或用户要求时再展示相关部分。
- 向用户展示整体定向和读者地图，允许调整顺序、合并、拆分、跳过或指定重点。用户确认的是讨论路径，不需要在尚未学习术语时审核完整取证清单。
- 初始地图是可修订的阅读假设。讨论暴露新理解断点时拆块，发现某部分没有信息增量时合并或跳过；session 保留变更，最终 deepnote 使用实际走过的结构。
- 用户可以覆盖深度判断。用户明确要求 deepnote 时，只要来源充分就执行；若来源不足，说明需要的 PDF、OCR 或版本。

### 第三步：逐块精读与讨论

1. 按确认后的阅读地图逐块推进；默认一次讨论一个一级块，复杂块按子块推进。进入当前块时先用两三句话说明它承接上一块的哪个结论、现在要填补哪个缺口。
2. 每块先说明原文在解决的具体失败，再引入专有术语；随后给出原文依据与 formulation、输入输出和中间状态、训练/推理流程、易懂解释、关键图表或实验结果、证据边界、局限与当前未知、与 Wiki 的连接。
   写作时不要把这些项目逐项填成清单；优先组织成“为什么会失败 → 论文怎样处理 → 实际怎样运行 → 证据支持到哪里”的连贯问题链。
3. 块结束时将内容压缩成“因为 A 失败，所以设计 B；B 应产生行为 C；证据 D 支持到 E”的因果链，帮助用户检查自己是否能复述机制。
4. 每个一级块结束时暂停，吸收用户追问、纠偏和判断。围绕当前块可以继续讨论多轮；用户确认“继续”、“下一块”或同等意思后，再进入下一块。
5. 将用户确认的重点、反对意见和解释选择绑定到对应块，并据此更新尚未阅读的地图，避免最后统一堆进“用户观点”附录。

### 第四步：写入与重构

用户说“写入 Wiki”“按这个重点整理”“把刚才的讨论保留下来”后：

1. 完整读取当前 session，识别已经确认的结论、用户纠偏、仍有分歧的判断与未解决问题；再回到原始来源核验进入 Wiki 的关键 claim。
2. 在 `raw/` 保存合法的小型材料或来源指针，不复制无权发布的全文。
3. 创建或更新对应来源页，设置 `type: glance` 或 `type: deepnote`。deepnote 使用讨论时确认的一级块作为 `##`、子块作为 `###`，并必须包含全文阅读后校准的 `## 摘要翻译`；同时检查模板要求是否被覆盖。同一来源升级时原地修改，不建立重复页面。
4. Deepnote 创建或更新同 slug 的 evidence sidecar，为每个 `## / ###` 块保留稳定 ID；只把已经区分性质与核验状态的关键结论写成 claim，不为填满面板制造证据条目。
5. 更新所有真正受影响的概念、主题和开放问题页；不要为了显得完整而强行拆页。
6. 回写对话中产生且用户确认的解释、比较或批评，将其与许可合规的关键图表一起放回对应讨论块，并明确标注性质与来源。
7. 按 `writing.md` 做第二遍语言修订，清理生硬译词、无动作的名词堆叠和实验成绩单式段落；不得在润色时改变技术定义或证据强度。
8. 更新 `index.md` 和 `log.md`，运行完整验证并提交当前任务相关改动。
9. 报告写了什么、改变了什么、还有什么未知；未经明确要求不 push 或发布。

## 追问

当用户围绕已读材料追问：

1. 先从 `index.md` 定位少量 Wiki 页并基于现有笔记回答。
2. 关键事实不确定、页面互相冲突或证据不足时，再回到 `raw/` 或公开原文。
3. 回答中区分论文声称、相关文献、分析推断与未知，并链接相关页面。
4. 默认不写文件；只有用户要求保留，或本轮一开始已经授权持续记笔记时才回写。
5. 回写时优先修订已有页；只有形成独立、长期有用的知识对象时才新建页。

## Lint 与回顾

用户说“整理笔记”“检查知识库”“回顾最近阅读”时：

- 结构检查：死链、孤儿页、重复页、frontmatter 和目录不一致。
- 知识检查：矛盾、过时主张、缺少来源的强断言、薄弱概念和未闭合线索。
- 深度检查：glance 是否足以支持阅读价值判断；deepnote 是否来自全文取证和完整分块讨论，是否包含摘要翻译、完整论证、关键反例和真正改变判断的研究响应。
- 结构检查：deepnote 是否保留讨论时确认的分块树，子块是否仍能说明其上位问题，固定模板是否误压平了论文结构。
- 地图检查：精读开始前是否先建立整体因果定向；读者地图是否通过陌生词测试；每块是否说明读完后新增的判断能力；取证清单是否误占了面向用户的地图。
- 图表检查：关键方法图和决定性实验是否进入对应块，裁剪是否保留坐标、图例与条件，版权不明的原图是否已改为重绘或表格重建。
- 阅读回顾：近期来源改变了哪些既有认识，还有哪些问题值得读下一篇材料。
- 可安全判断的问题直接修复；需要用户取舍的解释冲突先讨论。

## 常用说法

```text
判断这篇论文是否值得精读，先和我讨论，不要写入 Wiki：<路径或 URL>
```

```text
按“方法为什么有效”这个重点，把它升级为 deepnote。
```

```text
先给我这篇论文的整体因果定向和读者地图；取证与图表计划分开维护，再按块讨论，每个一级块结束后暂停。
```

```text
直接把这篇论文入库；先判断深度，值得精读就生成 deepnote，否则保存 glance。
```

```text
根据现有 Wiki 回答这个问题。先不要修改文件：<问题>
```

```text
把刚才的答案沉淀成主题页，并更新受影响的旧页面。
```

```text
回顾最近五次阅读：哪些结论变强了，哪些仍有冲突，下一步该读什么？
```
