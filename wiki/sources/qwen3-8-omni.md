# Qwen3.8-Omni：从全模态交互到原生全模态 Agent

## 摘要翻译

本文介绍 Qwen3.8-Omni-Flash：一个面向真实世界多模态生产力的原生多模态 Agent 模型。此前的 Omni 模型主要强调感知与交互；相比之下，Qwen3.8-Omni-Flash 显著增强了多模态理解与推理，以及长时程 Agent 任务上的表现。

这些能力由原生多模态联合训练策略支撑。该策略在保留较强文字领域能力的同时，促进 Agent 能力从文字任务迁移到音频和视频任务。模型继承 Qwen3.8-Next 的稀疏混合专家（MoE）架构，并把上下文窗口扩展到一百万 token，以支持长上下文多模态推理和长时程规划。

这些进展使模型能够作为主 Agent 或专用子 Agent 接入生产工作流，支持视频编辑、长音视频翻译、以音乐为条件的音乐视频或电影生成，以及基于视频生成笔记或 Omni Skill。针对现有 Agent Harness 缺少原生音视频支持的问题，论文发布了 Qwen-MM-Plugins：一个面向多模态生产力的轻量开源插件框架。

论文还把实时多模态交互界定为系统级挑战，需要编排上下文与记忆管理、工具使用和子 Agent 委托。为此，作者发布 Qwen-Live-Harness：一个基于 Qwen3.8-Omni-Flash 构建响应式实时多模态 Agent 的开源框架。

大规模评测显示，Qwen3.8-Omni-Flash 在多模态理解、推理、长时程 Agent 执行和视频生产力任务上表现较强。作者认为，这些结果和配套开源工具共同支持把 Qwen3.8-Omni-Flash 作为研究与生产中部署原生多模态 Agent 的实用基础。

摘要来源：Qwen3.8-Omni: Towards Native Omni-Modal Agents，arXiv v1。

## 问题空间

### 为什么读

这篇论文把 Omni 模型的目标从“看、听、说”推进到长程生产任务：模型要主动定位音视频证据、调用工具、读取执行反馈并继续行动。它值得 deepnote，因为论文同时覆盖模型内部的音频与长上下文表示，以及模型外部的插件、Harness 和 memory；只有把两层分开，才能判断所谓“原生 Agent”究竟新增了什么。

### 研究问题与价值

**论文声称。** Qwen3.8-Omni-Flash 面向需要文字、图像、音频和视频共同参与的生产力任务。作者集中解决三类障碍：长视频带来存储、传输和 token 成本；常见 Agent harness 难以在主模型上下文中处理流式音视频；现有 Omni 模型在长程工具执行和生产任务上的训练与评测不足。

价值来自任务闭环的变化。被动模型只能回答已经放进上下文的素材；全模态 Agent 可以先读低成本摘要，发现证据缺口，再加载原始片段、运行代码或媒体工具，并根据真实结果修正计划。若这个闭环可靠，长视频问答、会议处理、教程到可执行 Skill、媒体制作和小模型自动调优都能减少人工编排。

### 已有解法与缺口

[[qwen2-5-omni]] 已用 Thinker–Talker、TMRoPE 和流式编码统一视听交互；Qwen3-Omni 和 Qwen3.5-Omni 继续增强音频编码、推理、低延迟和长音视频处理。文字 Agent 则已经使用工具、沙箱、memory 和多步反馈。

此前路线仍有结构性断点：

- 模型能理解短音视频，不等于能在数小时材料中以可控成本找到稀疏证据。
- 长上下文模型可以接收更多 token，但标准 Attention 成本高，固定循环状态又可能遗忘精确细节。
- 文字 Agent 的工具接口通常只返回文本或静态图像，难以把时间连续的音视频直接纳入观察—行动循环。
- 综合 Agent 分数混合模型、工具、Harness 和执行环境，容易把系统能力全部归因于基础模型。

论文把稀疏骨干、空间音频、跨模态后训练和外部按需取证组合起来，但没有充分的因子化消融来分离各部分贡献。

## Idea 是怎样形成的

### 分析性思路重建

以下为分析性重建，只使用本文之前已有的架构和失败模式，不代表作者自述。

1. Thinker–Talker 已证明一个共享语言骨干可以接收多模态连续表示并输出文字或语音。下一瓶颈从“能否接入模态”转为“能否处理长材料并采取行动”。
2. 长音视频同时要求滚动理解和精确回看。固定状态递归层适合压缩长期历史，Attention 适合读取原始细节；将 GDN 与稀疏 Attention 交错，可以把两者分别用于“保持摘要”和“恢复证据”。
3. 稀疏 Attention 的难点是先知道该看哪里。可先让轻量 indexer 模仿稠密 Attention 的块级分布，再切换到真实 top-k 访问，降低一开始就稀疏训练造成的优化不稳定。
4. 模型内稀疏检索只能访问已经进入上下文的 token。数小时原始视频仍然昂贵，因此还需要模型外的 caption、结构化笔记、memory 和按时间读取工具，让 Agent 决定哪些片段值得送入模型。
5. 普通单声道音频只能较好表示“说了什么、是什么声音”。会议、场景理解和媒体制作还关心声源方向和运动，于是用并行 Spatial AuT 保留多通道幅度与相位差。
6. 单一后训练混合物很难同时优化推理、代码、视觉、音频和 Agent。先训练领域专家，再蒸馏轨迹到统一学生，最后进行跨模态 RL，是降低联合探索难度的一条工程路径。

这条推理把论文的内部机制和外部系统串起来：内部模型负责跨模态表示、推理与行动策略，外部系统负责证据按需载入和真实执行。

### 核心直觉

Qwen3.8-Omni 的核心 idea 是“先压缩形成工作理解，需要精确证据时再打开原文，并把取证本身变成 Agent 行动”。GDN 保存滚动状态，QSA 在已载入上下文中选块，外部 Agent 决定从原始音视频加载什么；三者对应三种不同尺度的记忆访问。

## 方法

### Problem setting 与 formulation

论文研究的不是单次多模态问答，而是长时程条件决策：模型接收文字、图像、音频、视频及工具返回的观察历史 $h_t$，在每一步生成文字、语音或结构化工具行动 $a_t$；Harness 执行动作并把新观察 $o_{t+1}$ 写回历史。模型内的 GDN 与 QSA 只处理已经载入的 token，外部插件决定哪些原始材料进入上下文。论文没有给出统一的 Agent 优化目标或预算约束，因此这一定义恢复的是系统接口；成功率、token、工具调用、墙钟时间与外部成本仍需分别衡量。

### 输入表示

文字经约 250K 词表的 tokenizer 变成 embedding。图像和动态采样视频帧进入视觉编码器。普通音频重采样为 16 kHz，以 25 ms 窗和 10 ms hop 计算 128 通道 Mel 频谱，再由 AuT 的卷积下采样与时间自注意力产生约 6.25 Hz 的连续表示。

空间音频走并行 Spatial AuT。输入先表示为一阶 Ambisonics 的 W/X/Y/Z 四通道，再对每个通道计算复数 STFT。实部、虚部和跨声道关系保留方向、距离与运动线索。各编码器输出经专用 adapter 投影到 Thinker 隐藏维度，并按时间顺序排列。论文还保留显式文字时间戳，让语言骨干直接读取源时间线。

### 长上下文骨干

Thinker 沿用 Qwen3.8-Next 的稀疏 MoE 骨干，交错使用 Gated DeltaNet（GDN）和 Attention。GDN 把历史压进固定大小循环状态，计算成本随上下文近似线性增长，但可能损失细节。Qwen Sparse Attention（QSA）先用轻量 indexer 给压缩 micro-block 打分，选择少数候选，再由核心 Attention 读取候选块的原始 token。

```text
GDN：持续更新滚动理解
QSA indexer：在已载入上下文中定位候选块
Attention：读取候选块的原始细节
外部 Agent：决定还要从原始材料加载哪些片段
```

QSA 和外部取证不能混为一谈。QSA 无法读取尚未进入上下文的第 73 分钟视频；时间读取工具可以先把那段视频送入上下文。

### 训练过程

预训练包含四阶段：S1 冻结语言骨干并对齐视觉、AuT 和 Spatial AuT；S2 解冻全部参数进行原生多模态联合训练；S3 冻结主干并让 QSA indexer 模仿稠密 Attention 的分布；S4 启用稀疏访问，联合优化主干与 indexer。原生长度为 262,144 token，后续扩展到 1M；论文未完整披露长度扩展配方。

后训练先从同一基础检查点得到通用指令、推理、代码、Agent、视觉和音频专家。每个专家经本领域 SFT 与 RL 后生成轨迹，统一学生模仿混合轨迹，再接受跨模态 RL。这样做能复用专业策略，但不会自动消除梯度冲突，也可能蒸馏教师错误。

### 一个完整 Agent pipeline

以两小时多人技术会议为例，用户要求“找出关于部署失败的讨论，给出带时间戳的原因，并生成修复清单”。

1. **低成本建图。** Omni-Caption 或 Video2Note 先生成分段摘要、人物和显式时间线。模型不立即加载全部原始音视频。
2. **计划取证。** Thinker从摘要中定位“部署、显存、超时”等候选段，通过插件读取对应时间范围；若涉及说话人归因，再请求 Spatial AuT 表示或更密集的视频帧。
3. **模型内检索。** 新载入片段进入长上下文。GDN保留会议整体状态，QSA选择相关 token 块，Attention读取精确措辞和画面证据。
4. **行动与校验。** Thinker产生工具调用，可能运行日志解析代码或读取附件；Harness执行后把真实结果返回。模型据此更新判断，证据不足时再次缩小时间范围。
5. **输出。** Thinker生成带时间戳的文字清单；需要语音时 Talker把结果转成流式语音。图像、视频或文档成品由外部工具生成，不是模型本体直接生成视觉 token。

完整能力因此应写成 `模型策略 + 工具集合 + 执行环境 + 记忆与编排`，详见 [[omni-agent-stack]]。

## 数学与理论

论文是系统报告，没有给出证明新性质的核心定理。最重要的形式化对象是空间声学表示和稀疏检索复杂度。

### Spatial AuT 为什么保留复数 STFT

对第 $c$ 个声道，短时傅里叶变换可写为

$$
X_c(\tau,\omega)
=\sum_n x_c[n]w[n-\tau H]e^{-j\omega n},
$$

其中 $w$ 是窗函数，$H$ 是 hop，$\tau$ 是时间帧，$\omega$ 是频率。若只保留幅度 $|X_c|$，跨声道相位差会丢失。保留复数实部和虚部后，可以计算相对相位

$$
\Delta\phi_{c_1,c_2}(\tau,\omega)
=\arg X_{c_1}(\tau,\omega)-\arg X_{c_2}(\tau,\omega),
$$

以及幅度比。这些量随到达时间差、声源方向和房间传播变化，为方向与运动估计提供信息。模型仍需从数据中学习映射；复数 STFT 只是保留可用线索，并不保证可靠定位。

### QSA 的选择与复杂度

把长度 $N$ 的上下文切成 $M=N/B$ 个 block，每块 $B$ 个 token。设 indexer 根据当前查询状态 $q$ 为第 $m$ 块产生分数

$$
s_m=f_\phi(q,\bar{k}_m),
$$

其中 $\bar{k}_m$ 是压缩块表示。选出 $K\ll M$ 个最高分 block 后，核心 Attention 只访问约 $KB$ 个原始 token。忽略 indexer 常数，单个查询的精确注意力访问从 $O(Nd)$ 降至 $O(KBd)$；若 $K$ 随长度保持较小，长上下文成本显著下降。

代价是离散召回瓶颈：关键块若不在 top-$K$，后续 Attention 无法补救。S3 用稠密 Attention 分布监督 indexer，本质上是在启用稀疏路径前降低这一选择误差。论文没有公开足够数据来量化跨模态关键块 recall，也没有证明 GDN、QSA 与外部 memory 的最优分工。

## 实验：问题、验证与答案

### Omni 化是否损伤文字与视觉能力？

**问题。** 加入音视频编码和跨模态训练后，通用文字、代码与视觉能力是否明显回退？

**实验。** 作者将 Qwen3.8-Omni-Flash 与 Qwen3.8-Flash、Qwen3.8-27B 等比较，覆盖 SWE-bench Pro、NL2Repo-Bench、IFBench、GPQA、视觉问答和视觉 Agent 基准。

**答案。** Omni 模型在多项任务上接近或略高于同代文字模型，也在部分任务略低，支持“能力大体共存”。这不是严格的训练预算对照，不能证明跨模态训练本身没有代价。

### 新模型是否改善音频和音视频能力？

**问题。** AuT、Spatial AuT 和跨模态训练是否带来可见增益？

**实验。** 作者在 ASR、多人语音、音频推理、音视频理解、长音视频、主动交互和空间音频基准上与 Qwen3.5-Omni-Plus、Gemini 3.8 Flash 等比较。

**答案。** 相对前代，多数音视频任务提高，例如 Audio MultiChallenge 从 57.6 提至 71.5，LVOmniBench 从 53.2 提至 63.3，OmniEchoBench 从 23.3 提至 43.9。模型并非全面领先：WenetSpeech Net、VoiceBench、WildSpeech 及多项音视频任务仍落后某些基线。由于架构、数据和后训练同时变化，不能把增益单独归因给 Spatial AuT。

### Agent harness 是否提高长音视频理解？

**问题。** 主动定位和验证证据是否比一次性静态理解有效？

**实验。** 同一 Qwen3.8-Omni-Flash 分别采用 Static 与 Qwen Code 设置，在 OmniVideoBench、Video-MME-v2 和 LVOmniBench 上比较；Gemini 3.8 Flash 也做对应比较。

**答案。** 论文中的同模型设置对照为：

| 基准 | Static | Qwen Code | 变化 |
| --- | ---: | ---: | ---: |
| OmniVideoBench | 63.4 | 67.8 | +4.4 |
| Video-MME-v2 | 65.0 | 71.3 | +6.3 |
| LVOmniBench | 63.3 | 73.6 | +10.3 |

三项成绩均提高，直接支持“Agentic 取证能改善这些基准”，也说明增益属于模型与 Qwen Code 的组合。论文没有把工具质量、额外 token、调用次数和模型策略做完整成本匹配。

### 模型是否具有更强的多模态工具执行能力？

**问题。** 相比前代，模型在外部工具与搜索任务上是否更强？

**实验。** 作者使用 WildClawBench-MM、UniClawBench、AgenticVBench 和 OmniGAIA；不同基准分别运行 Claude Code、OpenClaw 或无外部 harness 设置。

**答案。** Qwen3.8 相对 Qwen3.5 在四项均提高，在 WildClawBench-MM 与 UniClawBench 的列出模型中领先；Gemini 在 AgenticVBench 和 OmniGAIA 更高。不同基准执行环境不同，因此这些数字用于任务内比较，不能拼成纯模型能力排名。

### 能否形成真实迭代闭环？

**问题。** Omni Agent 能否观察音频错误、构造数据、训练并根据评测反馈继续迭代？

**实验。** Omni-Autoresearch 要求模型在 12 小时内改进 Qwen2.5-Omni-3B 的四川话识别。模型选择 WenetSpeech-Chuan、建立基线、听取错误、生成 3,413 条训练样本并做四轮实验。

**答案。** 同一评测集 CER 从 25.79% 降至 15.30%。这是有执行反馈的案例证据，证明一条特定工作流可以闭环；单任务、单次报告不足以证明广泛自主研究能力，也需要排查评测集过拟合和人工介入程度。

### 各组件分别贡献多少？

**问题。** 模型骨干、训练数据、QSA、多教师蒸馏、RL、插件和 Harness 的净贡献分别是多少？

**实验。** 论文没有提供覆盖这些变量的因子化消融。

**答案。** 未知。这是解读 Agentic claim 时最关键的限制。

## 贡献与边界

### Takeaways

- **问题**：如何让全模态模型以可控成本处理长音视频，并在工具反馈中完成长程任务？
- **核心 idea**：用 GDN 维持滚动状态、QSA 打开上下文内的原始证据、外部 Agent 按需加载上下文外的音视频。
- **可信结论**：整套模型与系统相对前代显著提高多项音视频和 Agent 基准；Qwen Code 取证在三个长音视频基准上稳定增益。
- **仍未证明**：这些增益有多少来自模型权重、训练配方、工具、Harness 或更高推理成本。
- **可复用启发**：模型内稀疏注意力与模型外取证解决不同问题；“原生 Agent”仍是模型和运行时共同构成的闭环。

### 最脆弱的假设

论文最脆弱的假设是：在异构 Harness 和工具预算下得到的 Agent 成绩，仍能主要反映模型自身的策略与多模态能力。若同一模型换 Harness 后排名大幅变化，或较弱模型在相同工具、提示、token 和调用预算下追平，那么“原生 Omni Agent”的强解释会退化为“一个有效的模型—系统集成”。论文已经在表注中承认执行设置不同，但尚未做足以拆分归因的对照。

## 研究响应

### 一周最小复现

目标是复现“主动取证优于静态输入”并测量代价，不尝试复现模型训练。

1. 选 20–30 个 30 分钟以上、答案依赖稀疏音视频证据的问题，预先标注关键时间段。
2. 固定同一可访问模型，比较 Static、固定均匀采样、Agent 按需读取三种设置。三者使用相同最终答案提示与总 token 上限。
3. Agent 只提供 `read_segment(start,end,resolution)`、转录和帧抽取三个工具，记录每次调用、载入时长、token、延迟和命中关键片段的比例。
4. 主要指标为答案准确率、evidence recall、每个正确答案的 token 与工具调用成本。
5. 若 Agent 只在预算更高时获益，或未提高 evidence recall，论文的“主动定位”解释需要收窄；若相同预算下稳定提高，系统级 claim 得到支持。

### 如何反驳：反例设计

构造带有大量高相似诱饵的长视频：真正答案需要第 73 分钟的一秒声音与第 12 分钟的画面联合判断，其余位置重复关键词、相似对象和错误字幕。再创建三种反事实：替换真实音频、打乱时间戳、让摘要遗漏关键事件。

用同一模型和相同 Harness 比较完整原始输入、摘要 + lazy loading、oracle 时间段和随机时间段。若 Agent 无法接近 oracle，或其成功主要依赖摘要已经泄漏答案，就反驳“模型能够根据不确定性主动找到证据”的强 claim。若 QSA 在关键片段已经载入后仍漏掉一秒事件，则暴露模型内稀疏选择的第二个瓶颈。

### 后续研究与新认知

检索截止 2026-10-03，距 arXiv v1 发布仅 11 天。尚未找到能够独立复现、扩展或反驳 Qwen3.8-Omni 核心结论的后续论文。当前可核验材料主要是论文与 Qwen 官方组件说明，因此这一节的“不存在”是受检索时间窗约束的未知，不代表以后不会出现。

与本文同时或更早的 benchmark 工作已经把 AgenticVBench、OmniGAIA、LVOmniBench 等问题显式化；它们提供评测场景，不构成对本文方法的后续验证。最值得追踪的后续证据是：同 Harness、同工具预算的模型对照，QSA 跨模态 block recall，Spatial AuT 在真实双声道和非标准阵列上的鲁棒性，以及 Omni-Autoresearch 的独立重复实验。

### Follow-up idea

**分析提案：以价值信息为目标的多模态证据预算器。** 现有粗到细取证主要优化答案与成本，却没有显式估计“再读取哪一段会让当前结论改变多少”。可以让 Agent 为每个候选片段预测条件价值信息

$$
\operatorname{VOI}(z)
=\mathbb{E}_{o_z}\left[U(a^*\mid o_z)-U(a^*\mid \mathcal{H})\right]-\lambda C(z),
$$

其中 $z$ 是候选音视频片段，$o_z$ 是读取后的观察，$\mathcal{H}$ 是当前证据历史，$U$ 表示答案效用或可校验任务回报，$C(z)$ 是 token、延迟与工具成本。Agent 只加载正 VOI 且最高的片段，并在每次观察后重新校准不确定度。

研究增量不只是换一个检索器。问题被重新定义为带成本的序贯实验设计，监督来自反事实：隐藏某片段后答案是否变化、读取它是否纠正错误、其代价是否值得。最小证伪实验使用带 oracle 证据段的长音视频集合；若 VOI 策略在相同准确率下不能减少载入 token，或在相同预算下不能提高 evidence recall，就应放弃该方向。

这是基于论文 limitation 提出的研究设想，未被本文验证，也未完成全面新颖性检索。
