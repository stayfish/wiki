# Qwen3.8-Omni：从全模态交互到原生全模态 Agent

## 为什么读

本轮阅读围绕四个问题展开：不同模态怎样进入统一语言骨干，语音与空间音频如何编码，模型如何完成长上下文训练，以及论文所称的 Agentic 能力究竟来自模型还是外部 Harness。用户尤其希望补齐 AuT、Spatial AuT、Thinker–Talker、QSA、多教师蒸馏和 Agent 运行时的背景。

## 一句话结论

Qwen3.8-Omni 的主要推进不是发明一种全新的 Agent 原理，而是把全模态感知、混合稀疏长上下文骨干、跨模态后训练与音视频工具系统组合起来，使模型从“看、听、说”进一步走向“主动找证据、调用工具并根据执行结果继续行动”。

## 问题与背景

此前的 Omni 模型已经能够接受文字、图像、音频和视频，并输出文字或实时语音，但真实的视听生产任务还要求：

- 在数小时材料中定位少量关键证据，而不是把所有内容反复塞进上下文；
- 保持音频、画面、人物和显式时间线的对应；
- 制定多步计划，调用搜索、代码、剪辑和生成工具；
- 根据工具的真实返回值纠错，而不是只生成一段貌似完成任务的文字；
- 在长期任务中管理上下文、记忆和后台子任务。

论文因此把目标从全模态感知与交互转向全模态生产力 Agent。

## 方法直觉

### 输入统一：统一的是表示空间，不是原始 token ID

文字先经过 tokenizer 得到离散 token ID，再通过 embedding lookup 变成向量。图像和音频并不先变成文字 token ID，而是由专门编码器直接产生连续表示：

```text
文字 ───────────────→ text embeddings ─┐
图像/视频 → Vision Encoder → embeddings ├→ Thinker 的共享表示空间
普通音频 → AuT ───────────→ embeddings ─┤
空间音频 → Spatial AuT ──→ embeddings ─┘
```

各编码器输出经过 modality-specific adapter/projector 对齐到 Thinker 的隐藏维度，然后按时间顺序进入统一序列。这里的“token”经常泛指序列位置；视觉和音频位置承载的是连续 embedding，不等于词表中的 token ID。

### 普通语音编码

普通音频重采样到 16 kHz，使用 25 ms 窗、10 ms hop 转成 128 通道 Mel 频谱。AuT 的四个 Conv2D block 将时间轴下采样 16 倍，随后使用时间自注意力形成带上下文的音频表示，最终约以 6.25 Hz 输出，即约每 160 ms 一个表示。

```text
波形 → 分帧/STFT → Mel 频谱 → Conv2D 下采样
     → temporal self-attention → 连续 audio embeddings
```

研究语言模型时可以把前处理抽象为 `waveform → [T_audio, d_audio]`，但不能忽略采样率、声道、压缩率、streaming/offline、mask 和训练推理预处理一致性。

### 空间音频编码

Spatial AuT 接收一阶 Ambisonics（FOA）接口，通常是 W/X/Y/Z 四通道。它处理各声道的复数 STFT，同时保留实部与虚部，因而能够利用跨声道幅度差和相位差推断声源方向、距离与运动。普通 AuT 更偏向回答“是什么声音、说了什么”，Spatial AuT 补充“声音从哪里来”。二者并行工作，并在同一时间轴上对齐。

### 时间怎样保留

时间信息同时存在于三个层次：

1. 序列顺序：音频 embedding 的索引天然保持先后，6.25 Hz 时第 `i` 个位置约对应 `i / 6.25` 秒；
2. 位置表示：位置 ID 让模型区分相对顺序；同一时间片的空间音频 embedding 共享时间索引但保留不同空间索引；
3. 显式时间戳：论文保留文本时间戳，将源时间线直接暴露给语言骨干，用于回答“何时发生”和对齐音画事件。

### Thinker–Talker 与输出不对称

Thinker负责多模态理解、推理、文本生成和工具调用；Talker读取Thinker隐藏状态，自回归生成离散语音 codec token，再由音频解码器还原波形。

```text
输入语音：波形 → AuT → 连续 embedding → Thinker
输出语音：Thinker hidden states → Talker → codec IDs → 波形
```

模型本体并不原生生成图像或视频 token。视觉成品由 Thinker 规划并调用外部图像、视频生成与编辑工具产生。因此这里的 Omni 更准确地表示全模态感知、文本/语音原生输出和工具增强的视觉生产，而不是任意模态原生输出。

### GDN、QSA 与 Attention

Thinker沿用 Qwen3.8-Next 的混合稀疏 MoE 骨干，并交错使用 Gated DeltaNet（GDN）和 Attention 层。GDN 持续把历史压缩进固定大小的循环状态，适合低成本传播长程信息，但可能丢失精确细节；Attention 能直接访问原始上下文 token，但标准实现对百万长度过于昂贵。

Qwen Sparse Attention（QSA）先让轻量 indexer 给压缩后的 micro-block 打分，只选择少量候选块，再让核心 Attention 读取候选块里的原始 token。三者可用以下分工理解：

```text
GDN：持续形成滚动理解
QSA indexer：判断原始证据可能在哪些块
Attention：打开候选块，恢复精确细节
```

它们共享同一残差流；Attention 找回的信息会进入后续 GDN 层。论文说明二者交错，但没有充分公开具体层间比例。

## 训练过程

### 四阶段预训练

1. **S1 编码器对齐**：语言骨干初始化自 Qwen3.8-Next 并保持冻结，分别对齐 Vision Encoder、AuT 和 Spatial AuT；先侧重 adapter，再训练编码器，避免未对齐表示破坏已有语言能力。
2. **S2 原生多模态联合预训练**：解冻全部参数，使用文本、音频、图像、视频和视频—音频数据联合训练，使不同模态从预训练阶段就进入同一个 Thinker。
3. **S3 QSA 预热**：冻结主干，保持稠密 Attention 工作，用其注意力分布监督 QSA indexer 学会块级选择。
4. **S4 QSA 联合训练**：正式启用 QSA，联合优化主干和 indexer，使模型适应只访问部分上下文块的稀疏模式。

预训练原生长度为 262,144 token，后续扩展到 1M；论文未完整披露长度扩展的全部配方。

### 多教师蒸馏与统一 RL

后训练先从同一基础检查点训练通用指令、推理、代码、Agent、视觉和音频等领域专家，每个专家使用本领域 SFT 和 RL，再产生高质量轨迹供统一学生模仿。随后学生在文本、视觉、音频和混合模态任务上统一 RL，以协调已经合并的能力。

多教师蒸馏不是本报告发明的新算法，而是已有的专家到通才训练范式。它与直接混合原始 SFT 数据的关键差别是：学生学习的是各专业策略经过 SFT+RL 优化后生成的行为轨迹，而不只是原始固定答案。它降低了统一模型同时探索所有领域策略的难度，但没有从数学上消除梯度冲突，也会继承教师错误。报告缺少足够消融来精确归因其增益。

Agent RL 尤其强调结果奖励：是否通过测试、工具是否执行成功、最终任务是否完成，比模型自称“已经完成”更重要。

## Agentic 能力

Agentic 能力不是单独的网络模块，而是一个闭环：

```text
理解目标 → 判断证据缺口 → 选择行动/工具
→ 读取环境反馈 → 修正计划 → 验证完成
```

对长视频，论文将传统的“一次性密集输入”改成粗到细、按需取证：先读 caption、结构化笔记或 memory，再定位相关时间段，加载原始音视频，证据不足时继续缩放范围或提高采样密度。这是主动感知，而不只是被动回答已经提供的内容。

必须区分两级检索：QSA 在已经进入模型上下文的 token 块中检索；外层 Agent 决定从外部世界加载哪段音频、视频或网页。QSA 不能读取尚未进入上下文的第 73 分钟视频，Agent 工具可以。

论文展示的场景包括长视频问答、多人会议、音乐到 MV、影视翻译、电影解说、Video-to-Note、从演示视频生成 Skill，以及根据音频错误迭代改进小模型。

## 模型、插件与 Harness 的边界

完整能力可以写成：

```text
Agentic capability
= 模型策略能力
+ 工具集合
+ 执行环境
+ 记忆与编排
```

- **模型**：多模态理解、跨模态推理、产生工具调用、判断返回结果；
- **Qwen-MM-Plugins**：按时间读取视频、生成摘要、编辑媒体、调用外部生成器；
- **Qwen-Live-Harness**：实时音视频会话、异步委托、审批与进度、主动提醒、持久记忆；
- **外部 Agent/工具**：实际运行代码、剪辑、搜索、生成图像或视频。

因此“原生 Agent”不表示所有行动都在模型权重内完成。其真正推进是让多模态观察直接参与计划、工具选择和反馈循环，而 Agent 的基本观察—行动—反馈范式本身并非新发明。参见 [[omni-agent-stack]]。

## 关键证据

- 相比 Qwen3.5-Omni-Plus，论文报告在 29 个音频推理、音视频推理和 Agent 评测上的平均分提升超过 25%；该数字是跨评测汇总，不能自动推出所有任务普遍更强。
- 普通 AuT 约以 6.25 Hz 输出表示；空间音频通过 FOA 复数 STFT 保留跨声道幅度和相位关系。
- 预训练采用 S1–S4 四阶段，将编码器对齐、全参数联合训练和 QSA 从教师预热到稀疏联合训练分开。
- 长视频 Agent 采用按需获取视听证据，而不是始终密集输入全部内容；论文报告音频和音视频 API 每小时输入成本显著下降，但这不等于完整系统总成本同幅下降。
- Qwen-Live-Harness 支持异步工具/子 Agent、主动交互和外部持久记忆；这些是系统能力，不应全部归因于基础模型。

## 局限与质疑

1. 模型、训练数据、QSA、多教师蒸馏、RL、插件和 Harness 的独立贡献缺少充分消融，能力归因困难。
2. 多教师蒸馏的轨迹筛选、教师冲突、是否使用 logits 以及关键超参数披露有限。
3. QSA 一旦漏选关键块，核心 Attention 就无法看到原始证据；报告没有充分量化跨模态 block recall。
4. 1M 上下文、GDN 状态、QSA 和外部 memory 的写入、遗忘与重载策略没有形成完整说明。
5. FOA 空间音频很有价值，但现实设备常是单声道、双声道或非标准阵列，声道转换和部署鲁棒性仍未知。
6. AuT 的约 160 ms 表示适合语义理解，但不能自动证明模型具备毫秒级唇音同步、节拍剪辑或重叠语音定位能力。
7. 论文突出 token 成本，而完整系统还包含预处理、多次工具调用、子 Agent、生成器和重试成本。
8. 很多内容生产任务带有主观质量，若主要依赖模型评分，需要额外的人类盲评、失败率和可复现实验。

这些问题汇总为 [[native-omni-agent-attribution]]。

## 与前代的关系

```text
Qwen2.5-Omni：统一看、听、说，建立 Thinker–Talker
        ↓
Qwen3.5-Omni：更长音视频、更精确时间对齐、更稳定语音
        ↓
Qwen3.8-Omni：长上下文、空间音频、跨模态后训练与 Agent 工作流
```

Qwen3.8 并未重新发明 Thinker–Talker，也沿用 Qwen3.5 的时间建模。其方法变化主要发生在长上下文骨干、Spatial AuT、训练配方和外层 Agent 系统。全模态模型的其他统一路线及后续阅读见 [[omni-model-architecture-paths]]。

## 阅读后的问题

- 如果其他模型使用完全相同的 MM-Plugins 和 Live-Harness，Qwen3.8 的优势还剩多少？
- 粗到细取证是模型真正根据不确定性自主决定，还是提示和固定工作流主导？
- QSA 在短暂音频事件、单帧数字和跨模态微小时序差上有多少漏检？
- 多教师蒸馏相对直接混合 SFT、直接统一 RL 的净收益和额外计算成本是多少？
- 长上下文和外部 Agent memory 应当如何动态分工？
