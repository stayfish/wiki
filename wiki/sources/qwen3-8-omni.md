# Qwen3.8-Omni · 从多模态感知到原生 Agent

## 来源

Qwen Team，2026，技术报告 [Qwen3.8-Omni: Towards Native Omni-Modal Agents](https://arxiv.org/abs/2609.25611)，arXiv:2609.25611v1，发布日期为 2026-09-22。

本页依据用户提供的 Zotero PDF 和公开 HTML 全文整理，阅读范围为全文。以下模型能力和实验数字均为论文作者报告，除非特别说明，不代表独立复现结果。

## 一句话

Qwen3.8-Omni-Flash 的关键变化不是简单增加输入模态，而是让同一个模型在文本、图像、音频、空间音频和视频上进行长程推理，再通过工具、记忆和子 Agent 将感知结果转化为可执行工作流。

## 要解决的问题

以往的 Omni 模型主要强调感知和实时对话，而视频编辑、长视频分析、会议跟进等生产任务还需要全局规划、时间推理、证据定位和多步工具执行。长音视频若一次性全部放入上下文，token、传输和存储成本也会随时长增长。

论文把问题拆成三层：模型需要原生处理多种模态；Agent 需要按需取得视听证据而不是始终密集读取；实时系统还要协调上下文、记忆、异步工具和子 Agent。

## 模型设计

Thinker 延续 Qwen-Omni 的 Thinker–Talker 结构，使用 Qwen3.8-Next 的混合稀疏 MoE 骨干。骨干把固定状态的 Gated DeltaNet 与注意力层交错使用，并通过 Qwen Sparse Attention 的轻量索引器选择相关上下文块。

视觉编码器处理图像和抽样视频帧，通用 AuT 编码器处理语音及一般声音，独立的 Spatial AuT 编码器从多声道音频的幅度和相位关系提取方向、距离和运动线索。各编码器的输出投影到 Thinker 的共享表示空间，并以显式时间戳保持音频、空间音频和视频事件的时间对齐。

预训练原生上下文为 262,144 token，论文称在后训练后扩展到 100 万 token。四阶段预训练依次完成编码器对齐、全参数多模态训练、稀疏注意力索引器预热和稀疏注意力联合训练。第二阶段报告使用约 2.5 万亿 token，覆盖文本、音频、图像、视频以及视听配对数据。

后训练先以多个领域专家教师蒸馏推理、代码、Agent、视觉和音频能力，再在混合模态任务上统一强化学习。长程 Agent 任务的奖励来自实际执行结果，而不是模型自己声称任务已经完成。

## 从理解到行动

对于长视频，模型可以先规划所需证据，再粗到细地调用工具读取相关音视频片段，并把音频和视觉分析分派给多个子 Agent。这种按需取证把长视频理解从一次性静态输入变成迭代搜索问题。

论文展示的工作流包括多人会议纪要与后续任务、音乐生成 MV、短剧翻译、长片解说、视频研究报告、教程转笔记以及从演示视频提取可执行技能。这些案例表达的是统一模型与工具链的设计空间，并不等同于所有工作流已经在任意环境中可靠自动化。

配套的 [Qwen-MM-Plugins](https://github.com/QwenLM/Qwen-MM-Plugins) 为既有 Agent harness 补充音视频能力，包括内容抽象、按需访问和生产工具；[Qwen-Live-Harness](https://github.com/QwenLM/Qwen-Live-Harness) 则面向实时交互，管理异步工具、子 Agent、主动通知和跨会话记忆。

## 证据

论文在文本、视觉、音频、视听和 Agent 基准上进行了广泛评测。作者报告，相比 Qwen3.5-Omni-Plus，模型在 29 项音频推理、视听推理与视听 Agent 评测上的平均分提升超过 25%；每小时音频和视听输入的估算 API 成本分别下降超过 98% 和 93%。这些百分比依赖论文设定、对比模型和价格假设。

在作者的 Omni-Autoresearch 案例中，模型在 12 小时内迭代改进一个四川话语音识别模型，生成 3,413 条训练样本，并将同一测试集上的字错误率从 25.79% 降到 15.30%。这是一个具体的系统案例，但单次内部实验不足以证明它能普遍自主完成模型研究。

论文还区分直接理解与 Agent 式证据收集，主张按需检索片段可同时改善长视听任务的准确率和 token 效率。带工具的结果应理解为模型与执行环境的联合表现，不能全部归因于基础模型本身。

## 边界与未确认项

- 这是一份由模型开发团队发布的技术报告，核心结果尚未在本 Wiki 中独立复现。
- 不同基准使用各自的 harness、采样和评分规则，横向比较需要同时查看表注与执行条件。
- 部分基准、语音克隆评测和生产案例为内部设置或依赖未完全公开的服务，外部可复现性仍需检验。
- 100 万 token 上下文并不意味着可以无成本地密集处理超长视频；论文自己的 Agent 方案仍依赖摘要、记忆与按需取证。
- 实时记忆、主动感知、声音克隆和自动执行会引出隐私、授权、误触发与身份滥用风险。论文伦理声明要求开发和部署者实施保护措施，但没有消除这些系统风险。
- 本页没有验证模型权重、服务可用性、API 定价或配套仓库在未来版本中的行为；这些状态会随时间变化。

## 对知识工作流的启发

论文中的 Video-to-Note 和 Skill Creator 与 [[knowledge-workflow|知识工作流]] 有直接联系：多模态模型可以从演示材料中抽取结构化笔记和操作步骤，但可追溯来源、证据核验和人工发布门槛仍不可省略。

更一般地，面对超长材料时，先建立摘要和索引、再按问题回到局部证据，往往比把全部原始内容长期塞入主上下文更可控。这是从论文系统设计抽象出的工作流启发，不是作者对所有知识库场景的直接实验结论。
