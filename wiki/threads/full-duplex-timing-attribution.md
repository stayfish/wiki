# 如何验证全双工模型真的保持了时间同步

## 为什么重要

[[minicpm-o-4-5]] 用约一秒一个 `chunk` 的方式组织输入输出，再让 TAIL 自回归预测 `boundary token`，决定当前 `chunk` 生成几个 text token。这足以构造按时间对齐的训练序列，却没有回答运行时最实际的问题：如果扬声器、网络或设备调度突然慢了半秒，模型知不知道播放器已经落后？只报告 RTF、CER/WER 或定性 demo 时，模型以为已经说到的位置、扬声器实际播到的位置和外部环境的当前时刻仍可能越来越远。

## 当前理解

real-time full-duplex 至少同时面对三个进度：模型已经生成到哪里、扬声器实际播放到哪里、外部环境此刻发生了什么。MiniCPM-o 4.5 在训练数据中用离线发音时间戳对齐前两者；推理时则依靠 `boundary token`、历史序列和 KV cache 决定下一步。公开材料没有显示模型会读取真实 playhead 或 queue length。

因此，更稳妥的理解是：TAIL 学到了训练数据里通常应该保持的时间节奏。真实播放一旦偏离这个节奏，它能不能自行恢复仍然未知。这个问题也适用于其他固定或动态 `window` 的 duplex 系统：改变模型生成协议，不等于模型已经看见播放器的真实状态。

## 支持证据

- [[minicpm-o-4-5]] Section 3.4 明确用 text token 的发音起止时间构造长度不同的 `chunk` 标签；前面说得快或慢，会改变后续 `chunk` 中应放多少文字。
- 官方推理实现显示动态长度来自自回归 boundary，常规窗有近固定语音 token 预算与最大文字 token guardrail，但未见公开的播放器误差变量。
- 论文 Table 12 的 RTF 说明优化运行时平均可以跟上现实时间；Table 10 只测可懂度与说话人相似度，没有测“还有多少音频没播”“环境变化后旧内容还播多久”以及系统恢复需要多长时间。
- 后续 AdaptDuplex 开始直接报告 interruption、delay、overlap 与 turn-taking 指标，说明交互时序可以脱离通用能力分数独立评估。

## 反例或冲突

- 模型每个 `chunk` 生成的文字量可以完全符合训练分布，而播放器仍会因为网络或设备抖动持续积压；如果模型看不到真实 queue，它没有可靠信号区别“正常播放”和“已经落后”。
- RTF 小于 1 只能说明平均计算吞吐足够，不能排除模型一次生成太多文字、旧波形没有取消或多次短延迟逐渐叠加。
- boundary 训练使用 teacher forcing；推理时过早或过晚的边界会改变后续历史，论文没有报告误差是否会自行恢复。
- AdaptDuplex 的系统结果同时改变模型规模、数据、`chunk` 策略和训练流程，不能把时序提升单独归因于动态 `chunk`。

## 缺少什么

需要在同一模型、speech decoder、运行时和数据上比较动态边界与匹配平均长度的固定边界，并记录：

| 指标 | 回答的问题 |
| --- | --- |
| 已生成但未播放的语音时长 $B(t)$ | 是否长期积压 |
| 环境改变后旧内容还会播放多久 | 新信息到达后，旧回答是否仍占着播放器 |
| 用户插话到旧波形停止的延迟 | 取消链是否有效 |
| 注入 300/600 ms 抖动后需要几个 `chunk` 恢复 | 策略能否发现并纠正播放器已经落后 |
| boundary 位置误差与 guardrail 触发率 | 动态长度是否来自正常预测 |
| CER/WER、SIM 与 RTF | 同步收益付出了多少质量和算力代价 |

还需要分别测试回声、重叠说话、长词、数字、停顿、代码切换与十分钟以上连续交互，避免短对话的平均分掩盖“待播放语音越积越多”的问题。

## 下一步

1. 在官方 MiniCPM-o 4.5 推理链中加入全阶段时间戳和真实播放器 acknowledgement；
2. 实现 TAIL 与 Fixed-N 两个只改变边界策略的设置；
3. 注入计算、网络和播放抖动，使模型内部历史与真实 playhead 主动分叉；
4. 再加入量化 queue-state token，比较原始 TAIL 与 Playback-Aware TAIL 的恢复速度；
5. 用人类盲评检查更低 backlog 是否以突兀停顿、漏词或语义破碎为代价。

## 何时算回答

当公开或可复现实验能在同一模型内同时报告质量、吞吐、待播放音频时长、旧内容继续播放的时间、打断残留和抖动后的恢复速度，并通过真实 queue-state 干预区分“只依赖生成历史”与“能读取播放器反馈”时，可以将本线索闭合为全双工时序控制主题页。
