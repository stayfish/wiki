# 如何验证“原生全模态 Agent”的能力归因

## 为什么重要

全模态 Agent 的展示往往同时更换基础模型、上下文机制、训练数据、工具、记忆和运行时。最终任务成功并不能说明是哪一层产生了增益，也难以判断换用另一个模型或相同 Harness 后能否复现。

## 当前理解

[[qwen3-8-omni]] 支持模型直接理解音视频、生成工具调用并根据执行结果继续行动；Qwen-MM-Plugins 和 Qwen-Live-Harness 则提供媒体操作、异步任务、主动提醒与持久记忆。系统整体具有 Agentic 能力，但“原生”应理解为多模态观察进入决策闭环，而不是所有工具和记忆都内化在模型权重中。

## 支持证据

- 论文将模型架构、Agent 应用和实时 Harness 分开描述，说明完整能力确实跨越多层系统。
- 长视频方案通过外部摘要、memory 和按需片段访问降低主上下文负担。
- Agent任务强调执行结果奖励，而不是模型自报完成，为真实闭环提供了训练信号。

## 反例或冲突

- 同一模型配备更好的工具接口可能显著提高成功率，因此产品演示不足以证明基础模型更强。
- 粗到细检索可能由预设 workflow 或 prompt 主导，未必代表模型自主形成稳定的主动感知策略。
- token 成本下降不等于总 GPU 时间、工具费用、调用次数和墙钟时间下降。
- 多教师蒸馏、QSA 和 1M context 的独立消融不足，无法确定主要增益来源。

## 缺少什么

需要统一任务和相同工具条件下的交叉实验：

| 对照 | 要回答的问题 |
| --- | --- |
| Qwen3.8，无工具 | 模型本身的理解与规划上限 |
| Qwen3.8 + 固定 workflow | 预设流程能贡献多少 |
| Qwen3.8 + 自主工具选择 | 自主策略带来的净增益 |
| 其他模型 + 同一 Harness | 增益是否主要来自运行时 |
| Dense Attention 与 QSA | 稀疏化的效率—召回权衡 |
| 直接混合训练与多教师蒸馏 | 训练配方的净收益和成本 |

同时应报告任务成功率、证据召回、总计算与工具成本、失败恢复次数、人类盲评和多次运行方差。

## 下一步

1. 阅读 SWE-agent 与 OpenHands，建立 Harness 和 Agent-Computer Interface 的评估框架；
2. 阅读 Qwen-MM-Plugins 与 Qwen-Live-Harness 源码，标出模型决策和固定代码路径的边界；
3. 查找 QSA、长视频 Agent 与多教师蒸馏的详细消融；
4. 对比至少一个采用相同工具集的非 Qwen 模型。

## 何时算回答

当公开材料或可复现实验能够在相同任务、预算和工具条件下，分别量化模型、检索、训练、插件与 Harness 的贡献，并公开主要失败模式时，可以将本线索闭合为一篇评估主题页。
