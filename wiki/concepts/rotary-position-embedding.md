# RoPE：用绝对旋转产生相对位置

## 一句话

RoPE 在注意力点积前按绝对位置旋转 Query 和 Key；两个旋转在点积中合成为位置差，因此注意力分数能够感知相对位置。M-RoPE 保留同一机制，只把不同旋转维度组分配给时间、高度和宽度坐标。

## 为什么需要它

没有位置编码时，注意力分数是：

```text
score(m,n) = q_mᵀ k_n
```

公式只比较内容向量，没有位置 `m,n`。RoPE 希望在保留内容匹配的同时，让分数依赖两个 token 的相对距离，而且不为每个相对距离额外维护偏置表。

## 直觉

把二维向量看成平面上的箭头。位置越靠后，箭头旋转得越多。比较两个旋转后的箭头时，共同旋转会抵消，只留下它们之间差了多少角度；这个角度差对应相对位置。

真实模型把高维 Query 和 Key 拆成许多二维对子。每对以不同速度旋转：快频率对短距离敏感，慢频率能跨更长位置变化。多种频率共同形成位置表示。

## 怎么工作的

### 一对维度的旋转

二维旋转矩阵为：

```text
         [ cos φ  -sin φ ]
R(φ)  =  [ sin φ   cos φ ]
```

对位置 `m`，RoPE 用角度 `mθ` 旋转 Query；位置 `n` 的 Key 用 `nθ`：

```text
q'_m = R(mθ) q_m
k'_n = R(nθ) k_n
```

注意力点积变成：

```text
q'_mᵀ k'_n
= q_mᵀ R(mθ)ᵀ R(nθ) k_n
= q_mᵀ R((n-m)θ) k_n
```

最后只出现相对位置 `n-m`。因此 RoPE 是“以绝对位置实施，以相对位置生效”。这里的位置不会独立决定注意力高低；结果仍同时依赖原始 `q_m,k_n` 的内容。

### 一个可手算的例子

令每移动一个位置旋转 30°，原始 Query 和 Key 都是 `(1,0)`：

```text
Query 位置 m=2：旋转 60°  → (0.5, 0.866)
Key   位置 n=5：旋转 150° → (-0.866, 0.5)
点积：0.5×(-0.866) + 0.866×0.5 = 0
```

两者相对距离是 `5-2=3`，即相对旋转 90°；直接计算 `(1,0)` 与其旋转 90° 后的 `(0,1)` 点积也为 0。若两个位置同时平移 10，位置差仍为 3，位置部分的作用不变。

### 高维向量与多频率

假设旋转维度为 8，可以分成四个二维对子：

```text
(q0,q1), (q2,q3), (q4,q5), (q6,q7)
```

第 `i` 对使用独立频率，常见形式为：

```text
θ_i = base^(-2i/d)
```

若 `base=10000, d=8`，四个频率约为 `1, 0.1, 0.01, 0.001`。位置 `p=5` 时，对应旋转角约为 `5, 0.5, 0.05, 0.005` 弧度。不同频率降低单一周期造成的位置混淆，并覆盖不同距离尺度。

### 在 Attention 中的位置

```text
hidden states
  → WQ/WK/WV 投影
  → 对 Q、K 应用 RoPE
  → Q_rotated K_rotatedᵀ
  → softmax
  → 与 V 加权求和
```

RoPE通常作用于 Query 和 Key，因为相对位置通过它们的点积进入注意力分数；Value 通常不旋转。向量化实现预先计算 `position × frequency` 的正弦、余弦，再利用 `rotate_half(x)` 所表示的 `(x,y) → (-y,x)` 完成：

```text
x_rotated = x × cos(angle) + rotate_half(x) × sin(angle)
```

代码库可能使用相邻维度配对，也可能把向量前后两半配对；只要维度排列、正余弦表和旋转操作一致，数学机制相同。

### M-RoPE：把旋转维度分给多个坐标轴

普通 RoPE 的所有维度对读取同一个位置 `p`。M-RoPE 给每个 token 坐标 `(t,h,w)`，将旋转维度对分成三组：

```text
时间组：角度 = t × 该维度对的频率
高度组：角度 = h × 该维度对的频率
宽度组：角度 = w × 该维度对的频率
```

旋转公式和注意力计算都没有改变。两个视觉 token 的坐标若为：

```text
A = (t=7, h=2, w=3)
B = (t=9, h=2, w=4)
```

点积中的三个相对坐标就是：

```text
Δt=2, Δh=0, Δw=1
```

时间组感知两单位时间差，高度组得到零位移，宽度组感知向右一格。

### 为什么 `(p,p,p)` 等价于一维 RoPE

文本或一维音频的三个 ID 都设为 `p` 时：

```text
时间组使用 pθ0, pθ1, ...
高度组使用 pθi, pθi+1, ...
宽度组使用 pθj, pθj+1, ...
```

所有旋转维度对都按同一个位置 `p` 乘自己的原有频率，所以合起来就是普通一维 RoPE。三个组仍然存在，旋转也没有消失；只是 `h,w` 没有独立于 `t` 变化，因此没有提供额外的二维空间坐标。

对于两个音频位置 `(5,5,5)` 与 `(8,8,8)`，三组相对 ID 都是 3。整个旋转空间看到的是同一个一维距离 3。

### 从 M-RoPE 到 TMRoPE

Qwen2-VL 的 M-RoPE 对文本使用 `(p,p,p)`，对图像使用固定时间和变化的 `(h,w)`，对视频则逐帧增加 `t`。[[qwen2-5-omni]] 的 TMRoPE 进一步让 `t` 对应约 40 ms 的实际时间，使可变帧率视频与音频进入共同时间尺。

## 适用条件

- 输入经过基于 Query–Key 点积的 Attention；
- 一维序列需要相对顺序，或图像、视频需要多轴相对位置；
- 多模态坐标分配在训练和推理阶段保持一致；
- 训练覆盖足够的位置范围与排列，使模型学会使用这些旋转模式。

位置编码只提供关系坐标，不提供内容语义。音视频具有相同时间 ID，表示模型能够识别它们同期；是否学会“画面中的杯子对应这次碎裂声”仍依赖训练数据、目标和注意力学到的内容关联。

## 容易混淆的概念

- **位置 ID 与向量维度索引**：位置 ID 是 `p` 或 `(t,h,w)`；维度对决定用哪个频率及读取哪个坐标轴。
- **绝对实施与相对效果**：Q、K 分别按绝对位置旋转，点积后出现位置差。
- **旋转与移动 token**：RoPE 不改变序列顺序，也不把 token 物理移动到别处，只改变 Q、K 的方向。
- **共享 ID 与丢失位置**：三轴 ID 相同仍保留一维位置；丢失的是轴之间独立变化所能表达的空间结构。
- **时间对齐与语义对齐**：相同时间坐标表示同期，不自动证明两种事件具有因果或语义对应关系。
- **M-RoPE 与 TMRoPE**：M-RoPE 是多轴旋转框架；TMRoPE 给时间轴实际时间刻度并用于音视频对齐。

## 证据与争议

Qwen2-VL 明确将 M-RoPE 描述为把原始旋转维度拆成 temporal、height、width 三部分；纯文本三组使用相同 ID，图像固定时间 ID，视频逐帧增加时间 ID。论文消融报告 M-RoPE 对若干评测有帮助，但其结果同时依赖模型、数据和任务，不能推成所有多模态架构都应使用同一坐标方案。

苏剑林从兼容性、等价性和对称性分析多模态 RoPE。他认为 Qwen2-VL 的 M-RoPE 保留了纯文本退化为一维 RoPE 的兼容性，但未严格保证：含 `wh` 个 patch 的图像在位置跨度上等价于 `wh` 个文本 token，以及图像前后文本到图像边界的距离对称。这是理论设计评论；文章也明确指出其实际重要性需要实验验证。

RoPE 的频率具有周期性，训练长度之外的外推还会受到频率基底、训练分布、数值分辨率和注意力模型本身影响。相对位置形式本身不保证无限长度可靠。

## 开放问题

- 多模态位置设计中的兼容性、patch 等价性和模态边界对称性各自对真实任务有多大贡献？
- 时间、空间轴应该平均分配旋转维度，还是根据视频长度、分辨率和任务动态分配？
- 对音视频瞬态事件，40 ms 时间刻度、视觉采样率和编码器下采样分别限制了多少时序精度？
- 训练长度外，M-RoPE 各轴的外推失败是否具有不同模式？
